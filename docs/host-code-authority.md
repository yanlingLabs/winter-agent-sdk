# Host Code authority helpers

These APIs are host capabilities. A serialized runtime config, tool input or guest execution snapshot must not supply their definitions, registrations, policy state or recovery proof.

`resolveHostCodeDescendantPolicy` reconstructs one descendant from a host-validated Agent invocation. It merges SDK builtins with host-prepared definitions, resolves the SDK's normalized agent type, computes the actual forced-mode inheritance, resolves registered/legacy tool identities, intersects the parent pool, and applies the normal subagent pool. The caller validates ancestry and preserves every ancestor's ask/deny rules. The returned definition denies must be added to the descendant's permission config, alongside complement denies for tools outside its returned pool. The helper reads no guest store or filesystem definitions.

`createHostCodeHookStage` uses the SDK's registry, interpreter, input validator, runner and reducer. Its host invoker must await and return a completed reviewer result. Callback launch or progress acknowledgements are not reviewer verdicts. Prepared wire groups can use `buildHookEntriesFromConfig`; prepared settings tiers can use `buildHookEntriesFromSettings`. Project/local registrations retain the normal workspace trust gate.

Broker output retention now uses per-process high/low watermarks: stdout and stderr pause at the high watermark and resume when acknowledgements reduce retained bytes and event count below half. Normal output no longer kills another row or a producer merely for exceeding the retention watermark; the commands' independent streamed-byte execution limit still applies. Workflow lifecycle/limit gaps remain separate review work. The existing release operation accepts `{ abandon: true, afterSequence: 0 }` for error cleanup, kills the owned process, discards unread bytes and removes its row. This does not extend process-close evidence to detached descendants.

Linux writer leases now treat a different kernel boot as unresolved ownership. A local PID's absence cannot establish that a foreign-kernel writer ended. `WinterCompatibilitySessionStore` accepts a host-only `leaseIdentity.confirmPreviousBootTerminated` callback for exclusive-store recovery after the previous kernel is proven terminated. Without that proof, recovery across VM cold boots is refused; ordinary same-kernel parent process restarts and reused PID checks retain their existing behavior. No runtime wire or model option enables recovery. macOS callers without Linux identity evidence cannot claim or steal Linux-stamped leases. Missing locks during a normal release/acquire race are retried through atomic creation, while malformed Linux lease records still require explicit recovery.

These changes do not close the SDK review's H1 service-delegation escape or H2 embedded execution-floor coverage, and do not implement VM isolation, active memory return, publication policy or Cowork production integration. The guest file-helper experiment remains unactivated.
